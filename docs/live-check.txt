== A correction worth recording ==
My first "phone check" used headless Chrome with --window-size=390,844 and the screenshot
showed the claim and the footer clipped at the right edge. It looked like a clear
responsive bug and I pushed a fix for it.

It was not a bug. --window-size does not set the layout viewport in headless-new: Chrome
rendered at a wider viewport and cropped the image to 390px, which looks exactly like
clipped text. The giveaway was that three genuinely different CSS versions produced
byte-identical PNGs - 24,917 bytes every time - which is impossible if the CSS were being
applied. Measuring in a real browser instead of eyeballing a screenshot settled it in one
call.

The commit message that claimed a fix has been corrected in the repo rather than left to
stand.
